# Interview Preparation

This track develops the ability to explain Java clearly, reason about code, solve problems and discuss engineering trade-offs.

It is not a memorisation sheet. Use it after studying the corresponding module.

## How to answer

Use this structure:

1. **Direct answer:** Respond to the exact question in one or two sentences.
2. **Reasoning:** Explain why the behaviour or design exists.
3. **Example:** Show a short example, trace or practical use case.
4. **Caveat:** Mention an important limitation or common misconception.
5. **Follow-up:** Be ready to go one level deeper.

## Interview levels

| Level | Skill being assessed | Practice format |
|---|---|---|
| Foundation | Correct definitions and terminology | Conceptual questions |
| Application | Correct use of APIs and language features | Short coding tasks |
| Internals | Understanding of execution and data structures | Tracing and implementation questions |
| Engineering judgement | Trade-offs, failure modes and maintainability | Scenario-based discussion |

## Question types

- Conceptual: define and compare related concepts.
- Output-based: predict exact output and explain each step.
- Debugging: locate compile-time, runtime and logic errors.
- Coding: implement a solution and discuss complexity.
- Scenario-based: choose an approach and defend trade-offs.
- Project-based: explain architecture, decisions, testing and limitations.

## Self-assessment rubric

Score each answer from 0 to 4:

- **0 — No answer:** Cannot explain the concept.
- **1 — Memorised:** Can repeat a definition but cannot explain it.
- **2 — Working knowledge:** Can explain and use a basic example.
- **3 — Strong:** Can discuss internals, edge cases and follow-ups.
- **4 — Interview-ready:** Can reason through unfamiliar scenarios and explain trade-offs clearly.

Aim for 3 or 4 across the important topics. A score is a reflection tool, not a guarantee of interview performance.
