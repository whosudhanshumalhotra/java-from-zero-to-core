# Coding Practice

The purpose of this track is to build problem-solving ability—not to collect copied solutions.

## Problem-solving routine

For every problem:

1. Restate the problem in your own words.
2. Identify inputs, outputs and constraints.
3. Work through a small example by hand.
4. Consider edge cases.
5. Describe a straightforward approach first.
6. Improve the approach only when there is a clear reason.
7. Implement readable Java code.
8. Test normal, boundary and invalid cases.
9. Analyse time and space complexity.
10. Explain the solution aloud as if in an interview.

## Difficulty levels

- **Easy:** Translate basic logic into correct code.
- **Medium:** Combine data structures and multiple steps.
- **Hard:** Reason about constraints, optimisation and competing approaches.

Difficulty is contextual. A problem that is easy after a topic is taught may be challenging before it.

| 01 | Number problems | Arithmetic, conditions, loops and numeric reasoning |
| 02 | Pattern problems | Nested loops and output tracing |
| 03 | Arrays | Traversal, frequency, prefix sums and two pointers |
| 04 | Strings | Character processing, frequency and transformations |
| 05 | Searching and sorting | Binary search, sorting and complexity |
| 06 | Recursion and backtracking | Base cases, call stack and state exploration |
| 07 | Hashing | HashMap, HashSet and frequency counting |
| 08 | Linked lists | Pointer/reference manipulation |

## Important rule

Attempt the problem before reading a solution. If you need a hint, take one hint at a time. After solving it, close the solution and implement it again from memory.
